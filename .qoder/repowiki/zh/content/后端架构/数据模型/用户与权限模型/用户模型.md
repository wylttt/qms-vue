## 用户实体字段定义

`SysUser` 实体类定义了用户信息表（sys_user）的所有字段，每个字段都有明确的数据类型、约束条件和业务含义。以下是主要字段的详细说明：

- **用户ID (userId)**: `Long` 类型，主键，唯一标识用户。
- **用户账号 (userName)**: `String` 类型，长度不超过30个字符，不能为空，且必须唯一。
- **用户昵称 (nickName)**: `String` 类型，长度不超过30个字符，用于显示用户名称。
- **用户邮箱 (email)**: `String` 类型，符合邮箱格式，长度不超过50个字符。
- **手机号码 (phonenumber)**: `String` 类型，长度不超过11个字符，用于接收短信验证码等。
- **用户性别 (sex)**: `String` 类型，'0'表示男，'1'表示女，'2'表示未知。
- **头像地址 (avatar)**: `String` 类型，存储用户头像的URL。
- **密码 (password)**: `String` 类型，使用BCrypt算法加密存储。
- **状态 (status)**: `String` 类型，'0'表示正常，'1'表示停用。
- **删除标志 (delFlag)**: `String` 类型，'0'表示存在，'2'表示已删除。

这些字段在数据库中的定义与实体类保持一致，确保了数据的一致性和完整性。

## 用户状态枚举与业务规则

用户状态通过 `UserStatus` 枚举类进行定义，包含三种状态：正常、停用和删除。具体定义如下：

- **OK("0", "正常")**: 用户账户处于正常状态，可以正常登录和使用系统。
- **DISABLE("1", "停用")**: 用户账户被停用，无法登录系统。
- **DELETED("2", "删除")**: 用户账户已被逻辑删除，不再显示在系统中。

当用户尝试登录时，系统会检查用户的状态。如果状态为“停用”或“删除”，则不允许登录，并返回相应的错误信息。此外，管理员可以在后台管理系统中修改用户状态，以控制用户的访问权限。

## MyBatis映射文件中的CRUD操作

MyBatis映射文件 `SysUserMapper.xml` 定义了用户表的CRUD操作，包括查询、插入、更新和删除。以下是关键操作的SQL实现：

### 用户信息与角色信息的联合查询

```xml
<select id="selectUserList" parameterType="SysUser" resultMap="SysUserResult">
    select u.user_id, u.dept_id, u.nick_name, u.user_name, u.email, u.avatar, u.phonenumber, u.sex, u.status, u.del_flag, u.login_ip, u.login_date, u.create_by, u.create_time, u.remark, d.dept_name, d.leader 
    from sys_user u
    left join sys_dept d on u.dept_id = d.dept_id
    where u.del_flag = '0'
    <if test="userId != null and userId != 0">
        AND u.user_id = #{userId}
    </if>
    <if test="userName != null and userName != ''">
        AND u.user_name like concat('%', #{userName}, '%')
    </if>
    <if test="status != null and status != ''">
        AND u.status = #{status}
    </if>
    <if test="phonenumber != null and phonenumber != ''">
        AND u.phonenumber like concat('%', #{phonenumber}, '%')
    </if>
    <!-- 数据范围过滤 -->
    ${params.dataScope}
</select>
```

此查询通过左连接 `sys_dept` 表获取部门信息，并根据条件动态构建WHERE子句，支持按用户ID、用户名、状态和手机号码进行筛选。

## 数据验证注解

在 `SysUser` 实体类中，使用了多种数据验证注解来确保输入数据的合法性。主要注解包括：

- **@NotBlank**: 确保用户账号不能为空。
- **@Size(min=0, max=30)**: 限制用户昵称和账号的长度不超过30个字符。
- **@Email**: 验证邮箱格式是否正确。
- **@Xss**: 防止XSS攻击，确保用户输入不包含脚本字符。

这些注解在用户注册或更新信息时生效，确保数据的完整性和安全性。

## 密码加密与敏感信息处理

### 密码加密存储机制

用户密码使用 `BCryptPasswordEncoder` 进行加密存储。`SecurityUtils` 工具类提供了加密和验证密码的方法：

```java
public static String encryptPassword(String password) {
    BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();
    return passwordEncoder.encode(password);
}

public static boolean matchesPassword(String rawPassword, String encodedPassword) {
    BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();
    return passwordEncoder.matches(rawPassword, encodedPassword);
}
```

当用户注册或修改密码时，系统会调用 `encryptPassword` 方法对明文密码进行加密；登录时，使用 `matchesPassword` 方法验证输入的密码是否与数据库中的加密密码匹配。

### 敏感信息脱敏处理

前端工具类 `security.js` 提供了敏感信息脱敏功能，例如手机号码和邮箱地址的脱敏：

```javascript
export function maskSensitiveInfo(data, type) {
    if (!data) return data;

    switch (type) {
        case 'phone':
            return data.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
        case 'email':
            return data.replace(/(.{2}).*(@.*)/, '$1***$2');
        default:
            return data;
    }
}
```

该方法在前端展示用户信息时调用，保护用户的隐私。

## 索引优化与安全机制

### 索引优化策略

在 `sys_user` 表中，`user_name` 和 `phonenumber` 字段上建立了索引，以提高查询效率。数据库脚本中定义如下：

```sql
CREATE TABLE `sys_user` (
  `user_name` varchar(30) NOT NULL COMMENT '用户账号',
  `phonenumber` varchar(11) DEFAULT '' COMMENT '手机号码',
  ...
  PRIMARY KEY (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户信息表';
```

虽然没有显式创建索引，但 `user_name` 作为唯一约束字段，数据库会自动为其创建唯一索引，确保查询性能。

### 用户登录失败次数限制

系统通过 `SysPasswordService` 类实现登录失败次数限制。配置文件 `application.yml` 中定义了最大重试次数和锁定时间：

```yaml
user:
  password:
    maxRetryCount: 5
    lockTime: 10
```

当用户连续登录失败超过5次时，账户将被锁定10分钟。相关逻辑在 `SysPasswordService.validate` 方法中实现，使用Redis缓存记录失败次数。
