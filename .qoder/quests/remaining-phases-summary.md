### 核心模块（3个）

#### 1. 采血预约管理（3天）

**需要创建的文件**:
- `GcBloodAppointment.java` - 采血预约实体类
- `BloodAppointmentVO.java` - 预约视图对象
- `GcBloodAppointmentMapper.java` - Mapper接口
- `GcBloodAppointmentMapper.xml` - MyBatis配置
- `IGcBloodAppointmentService.java` - Service接口
- `GcBloodAppointmentServiceImpl.java` - Service实现
- `GcBloodAppointmentController.java` - Controller

**功能清单**:
- [ ] 采血预约CRUD
- [ ] 预约列表查询（关联居民、采血点）
- [ ] 预约状态管理
- [ ] 预约时间冲突检测
- [ ] 批量预约
- [ ] 导出预约列表

**API接口**（约8个）:
1. GET /api/gc/blood/appointment/list
2. GET /api/gc/blood/appointment/{id}
3. POST /api/gc/blood/appointment
4. PUT /api/gc/blood/appointment
5. DELETE /api/gc/blood/appointment/{id}
6. PUT /api/gc/blood/appointment/status
7. POST /api/gc/blood/appointment/batch
8. POST /api/gc/blood/appointment/export

#### 2. 第三方系统对接（5天）⭐核心

**需要创建的文件**:
- `GcPushLog.java` - 推送日志实体类
- `GcPushLogMapper.java` - Mapper接口
- `GcPushLogMapper.xml` - MyBatis配置
- `IBloodSystemPushService.java` - 第三方推送Service接口
- `BloodSystemPushServiceImpl.java` - 推送Service实现
- `BloodSystemCallbackController.java` - 回调接口Controller
- `PushRetryTask.java` - 推送重试定时任务
- `ThirdSystemConfig.java` - 第三方系统配置类

**功能清单**:
- [ ] 推送采血预约信息到第三方系统
- [ ] 接收第三方系统回调（采样状态更新）
- [ ] 推送失败自动重试（3次）
- [ ] 推送日志记录（请求/响应/耗时）
- [ ] 签名验证（保证回调安全）
- [ ] 推送日志查询

**API接口**（约5个）:
1. POST /api/gc/blood/push/{appointmentId} - 手动推送
2. POST /api/gc/blood/callback - 第三方回调接口
3. GET /api/gc/push-log/list - 推送日志列表
4. GET /api/gc/push-log/{id} - 推送日志详情
5. PUT /api/gc/push-log/retry/{id} - 手动重试

**技术要点**:
- HTTP客户端调用第三方接口
- 重试机制（指数退避策略）
- 异步推送（使用线程池）
- 签名算法（MD5/SHA256）
- 日志追踪（完整记录请求响应）

#### 3. 采样状态管理（2天）

**需要创建的文件**:
- 复用采血预约相关文件

**功能清单**:
- [ ] 更新采样状态（未采样/已采样）
- [ ] 采样状态查询
- [ ] 采样进度统计
- [ ] 采样完成率报表

**API接口**（约3个）:

2. GET /api/gc/blood/sampling/statistics
3. GET /api/gc/blood/sampling/report

## 🎯 建议开发顺序

### 立即开始：第三阶段（采血业务功能）

**优先级最高的原因**:
1. 采血业务是核心流程的重要环节
2. 第三方系统对接需要时间联调
3. 为第四阶段筛查结果录入提供数据基础

**推荐开发顺序**:
1. 先开发采血预约管理（独立功能，可先测试）
2. 再开发采样状态管理（依赖预约管理）
3. 最后开发第三方对接（最复杂，需要测试环境）

## ⚠️ 风险提示

### 第三阶段风险
- **第三方系统对接稳定性**: 需要与第三方厂商协调联调时间
- **推送重试机制**: 需要仔细设计，避免重复推送

### 第五阶段风险
- **OCR识别准确率**: 需要选择合适的OCR服务商
- **离线数据同步**: 需要设计冲突检测和解决机制
- **微信小程序审核**: 可能需要多次提交审核
