## 1. 项目概述

### 1.1 项目背景

濂溪区胃癌早期筛查项目是九江市濂溪区政府推出的重要民生工程，旨在通过系统化的问卷调查、采血筛查、胃镜检查和随访管理，实现胃癌的早发现、早诊断、早治疗，降低胃癌发病率和死亡率。

项目覆盖濂溪区全区居民，包括6个街道/乡镇（十里街道、五里街道、姑塘镇、莲花镇、新港镇、高垅乡）及其下属社区/村，预计服务人群规模达数万人。

### 1.2 项目目标

#### 业务目标
- 实现全区居民胃癌风险筛查的信息化管理
- 建立完整的"问卷调查-采血筛查-胃镜检查-随访管理"闭环流程
- 提高筛查效率，降低人工成本，减少数据错误
- 实现数据实时统计分析，为政府决策提供数据支持

#### 技术目标
- 构建基于Vue3 + Spring Boot的现代化管理系统
- 支持微信小程序端居民自主录入和协助录入
- 实现与第三方采血系统的标准化对接
- 支持全国五级行政区划扩展能力
- 实现精细化的数据权限控制

### 1.3 项目范围

#### 包含范围
- ✅ 管理后台系统（Vue3 + Ant Design Vue）
- ✅ 后端服务（Spring Boot + MyBatis）
- ✅ 小程序端（uni-app支持微信小程序和H5）
- ✅ 行政区划管理（支持省市区街道社区五级）
- ✅ 居民信息管理（支持OCR身份证识别）
- ✅ 问卷调查管理（动态问卷模板、重点人群判定）
- ✅ 采血点管理
- ✅ 任务分配与进度统计
- ✅ 采血预约管理（与第三方系统对接）
- ✅ 筛查结果管理（血液筛查结果）
- ✅ 随访对象管理
- ⚠️ 胃镜筛查结果管理（预留接口）

#### 不包含范围
- ❌ 第三方采血系统的开发（仅对接现有系统）
- ❌ 医院HIS系统集成（仅预留接口）
- ❌ 移动端App（仅支持微信小程序和H5）
- ❌ 短信通知功能（可后期扩展）

## 3. 功能需求

### 3.1 行政区划管理

#### 功能描述
支持全国五级行政区划（省、市、区/县、街道/乡镇、社区/村）的查询和管理，为其他业务模块提供区划数据基础。

#### 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|-------|
| F1.1 | 导入全国行政区划数据 | 支持导入国家标准行政区划SQL数据 | P0 |
| F1.2 | 查询省列表 | 查询所有省份信息 | P0 |
| F1.3 | 查询市列表 | 根据省份ID查询城市列表 | P0 |
| F1.4 | 查询区/县列表 | 根据城市ID查询区/县列表 | P0 |
| F1.5 | 查询街道/乡镇列表 | 根据区/县ID查询街道/乡镇列表 | P0 |
| F1.6 | 查询社区/村列表 | 根据街道ID查询社区/村列表 | P0 |
| F1.7 | 区划树形结构查询 | 递归查询构建区划树形结构 | P1 |
| F1.8 | 区划级联选择器 | 前端级联选择组件支持 | P0 |
| F1.9 | 新增区划 | 超级管理员手动新增区划（补充社区/村） | P2 |
| F1.10 | 编辑区划 | 超级管理员编辑区划信息 | P2 |
| F1.11 | 删除区划 | 超级管理员删除区划（检查关联） | P2 |

#### 业务规则
1. 行政区划代码采用国家标准12位代码（GB/T 2260）
2. 区划层级：1-省、2-市、3-区/县、4-街道/乡镇、5-社区/村
3. 删除区划需检查是否存在子级区划或被引用
4. 初始化时仅导入濂溪区相关数据，全国数据可选导入

#### 接口设计
- `GET /api/gc/region/provinces` - 查询省列表
- `GET /api/gc/region/cities?provinceId={id}` - 查询市列表
- `GET /api/gc/region/districts?cityId={id}` - 查询区列表
- `GET /api/gc/region/streets?districtId={id}` - 查询街道列表
- `GET /api/gc/region/communities?streetId={id}` - 查询社区列表
- `GET /api/gc/region/tree?rootId={id}&maxLevel={level}` - 查询树形结构
- `POST /api/gc/region` - 新增区划
- `PUT /api/gc/region` - 编辑区划
- `DELETE /api/gc/region/{id}` - 删除区划

### 3.3 问卷调查管理

#### 功能描述
管理问卷模板和问卷调查数据，支持动态问卷渲染，自动判定重点人群。

#### 功能列表

| 功能编号 | 功能名称 | 功能描述 | 优先级 |
|---------|---------|---------|-------|
| F3.1 | 问卷模板管理 | 管理问卷模板（增删改查） | P0 |
| F3.2 | 问卷模板版本管理 | 支持问卷模板版本控制 | P1 |
| F3.3 | 问卷填写（小程序端） | 居民或调查员填写问卷 | P0 |
| F3.4 | 问卷离线填写 | 调查员端支持离线填写 | P1 |
| F3.5 | 重点人群自动判定 | 根据评分规则自动判定 | P0 |
| F3.6 | 问卷数据查询 | 查询问卷填写记录 | P0 |
| F3.7 | 问卷数据统计 | 统计问卷完成情况 | P1 |
| F3.8 | 问卷数据导出 | 导出问卷数据 | P2 |

#### 问卷模板结构

濂溪区胃癌筛查问卷V1.0包含以下内容：

**问卷分节**
1. 基本信息（1题）
2. 既往病史（4题）
3. 家族史（2题）
4. 生活习惯（3题）
5. 症状评估（2题）

**评分规则**
- 每个选项对应风险评分（0-25分）
- 总分 = 所有选中选项评分之和
- 重点人群阈值：≥60分

**风险等级**
- 低风险：0-39分
- 中风险：40-59分
- 高风险：60分以上（标记为重点人群）

#### 业务规则
1. 问卷采用JSON格式存储，支持动态渲染
2. 支持单选题、多选题、问答题等题型
3. 支持条件显示逻辑（根据前置答案显示后续题目）
4. 问卷提交后自动计算评分并判定是否为重点人群
5. 离线填写的问卷在网络恢复后自动同步

#### 接口设计
- `GET /api/gc/questionnaire/template/list` - 查询模板列表
- `GET /api/gc/questionnaire/template/{id}` - 查询模板详情
- `POST /api/gc/questionnaire/template` - 新增模板
- `PUT /api/gc/questionnaire/template` - 编辑模板
- `DELETE /api/gc/questionnaire/template/{id}` - 删除模板
- `POST /api/gc/questionnaire/record` - 提交问卷
- `GET /api/gc/questionnaire/record/list` - 查询问卷记录

## 5. 业务流程

### 5.1 居民录入与问卷流程

```
开始
│
├─ 录入方式选择
│  ├─ 居民自主
│  │  └─ 小程序注册登录
│  │     └─ OCR扫描身份证
│  │        └─ 自动填充基本信息
│  │           └─ 填写胃癌调查问卷
│  │              └─ 系统自动评分
│  │                 └─ 判定是否重点人群
│  │                    └─ 保存数据
│  │
│  └─ 调查员协助
│     └─ 调查员小程序登录
│        └─ 帮助居民OCR扫描身份证
│           └─ 协助填写基本信息
│              └─ 协助填写问卷
│                 └─ 系统自动评分
│                    └─ 判定是否重点人群
│                       └─ 保存数据（记录调查员ID）
│
└─ 结束
```

### 5.2 采血预约流程

```
sequenceDiagram
    participant 居民
    participant 小程序
    participant 本系统后端
    participant 第三方采血系统
    participant 采血点

    居民->>小程序: 选择采血点和预约时间
    小程序->>本系统后端: 提交预约信息
    本系统后端->>本系统后端: 保存预约记录
    本系统后端->>第三方采血系统: 推送预约信息(API)
    
    alt 推送成功
        第三方采血系统-->>本系统后端: 返回预约ID和条码号
        本系统后端-->>小程序: 预约成功
        小程序-->>居民: 显示预约成功
    else 推送失败
        第三方采血系统-->>本系统后端: 返回错误
        本系统后端->>本系统后端: 重试机制(最多3次)
        alt 重试成功
            本系统后端-->>小程序: 预约成功
        else 重试失败
            本系统后端-->>小程序: 预约失败
            小程序-->>居民: 提示重新预约
        end
    end
    
    第三方采血系统->>采血点: 生成条码并打印
    采血点->>采血点: 采集血样
    第三方采血系统->>本系统后端: 回调通知采样完成
    本系统后端->>本系统后端: 更新采样状态为"已采样"
```

   │           └─ 定期随访

   └─ 结束

## 8. 接口需求

### 8.1 第三方系统对接

#### 8.1.1 推送采血预约信息

**接口说明**: 本系统向第三方采血系统推送居民预约信息

**接口地址**: `POST /api/external/blood/appointment`

**请求参数**:
```json
{
  "appointmentId": "本系统预约ID",
  "residentName": "居民姓名",
  "idCardNo": "身份证号",
  "gender": "性别",
  "age": 45,
  "contactPhone": "联系电话",
  "siteCode": "采血点编码",
  "siteName": "采血点名称",
  "appointmentTime": "2025-12-20T09:00:00"
}
```

**响应参数**:
```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "thirdSystemId": "第三方系统生成的预约ID",
    "barcodeNumber": "条码编号"
  },
  "requestId": "请求追踪ID"
}
```

#### 8.1.2 接收采样状态回调

**接口说明**: 第三方采血系统回调通知本系统采样完成

**接口地址**: `POST /api/gc/blood/callback/sampling-status`

**请求参数**:
```json
{
  "thirdSystemId": "第三方系统预约ID",
  "appointmentId": "本系统预约ID",
  "barcodeNumber": "条码编号",
  "samplingStatus": "sampled",
  "samplingTime": "2025-12-20T09:30:00",
  "operatorName": "操作人姓名"
}
```

**响应参数**:
```json
{
  "code": 200,
  "message": "成功",
  "requestId": "请求追踪ID"
}
```

#### 8.1.3 推送重试机制

- 首次推送失败后，等待30秒进行第二次尝试
- 第二次失败后，等待60秒进行第三次尝试
- 三次均失败，标记为推送失败，通知管理员
- 支持管理员手动触发重新推送

#### 8.1.4 推送日志记录

所有推送请求和响应完整记录到`gc_push_log`表，包括：
- 请求URL、请求体、响应码、响应体
- 推送状态、重试次数、耗时
- 错误信息、推送时间
