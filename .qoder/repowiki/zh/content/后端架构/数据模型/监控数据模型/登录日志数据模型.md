## 字段定义与业务含义

登录日志（SysLogininfor）数据模型用于记录系统用户的登录行为，包含以下核心字段：

| 字段名 | 数据类型 | 业务含义 | 约束条件 |
|--------|----------|----------|----------|
| infoId | Long | 主键ID，唯一标识一条登录日志记录 | 非空，自增主键 |
| userName | String | 用户账号，标识登录系统的用户身份 | 非空，最大长度50字符 |
| status | String | 登录状态：0表示成功，1表示失败 | 非空，枚举值限制 |
| ipaddr | String | 登录请求来源的IP地址 | 非空，IPv4或IPv6格式 |
| loginLocation | String | 登录地理位置，通过IP解析得出 | 可为空，最大长度255字符 |
| browser | String | 用户使用的浏览器类型（如Chrome、Firefox） | 可为空，最大长度255字符 |
| os | String | 用户操作系统（如Windows 10、macOS） | 可为空，最大长度255字符 |
| msg | String | 登录提示消息，描述登录结果详情 | 可为空，最大长度255字符 |
| loginTime | Date | 用户发起登录请求的时间戳 | 非空，默认为当前数据库时间 |

**字段映射说明**：Java实体类中的属性与数据库字段通过MyBatis resultMap进行映射，遵循驼峰转下划线规则（如`loginTime` → `login_time`）。

## @Excel注解在数据导出中的作用

`@Excel`注解用于配置实体类字段在导出为Excel文件时的显示规则和数据转换逻辑。其主要功能包括：

### 字段名称映射
通过`name`属性将Java字段映射为Excel列标题，实现中文化展示：
```java
@Excel(name = "用户账号")
private String userName;
```
上述代码将`userName`字段在导出时显示为“用户账号”。

### 值转换规则
使用`readConverterExp`属性实现枚举值的可读性转换：
```java
@Excel(name = "登录状态", readConverterExp = "0=成功,1=失败")
private String status;
```
该配置将数据库中的`0`和`1`分别转换为“成功”和“失败”显示在Excel中。

### 日期格式化
通过`dateFormat`属性统一日期输出格式：
```java
@Excel(name = "访问时间", width = 30, dateFormat = "yyyy-MM-dd HH:mm:ss")
private Date loginTime;
```
确保时间字段以标准格式呈现，避免Excel自动格式化导致的显示异常。

### 其他导出配置
- `width`: 设置列宽
- `cellType`: 指定单元格类型（数值、字符串、图片）
- `suffix`: 添加单位后缀（如%）
- `defaultValue`: 空值时的默认填充内容

## MyBatis分页查询与条件筛选实现

### 分页查询机制
前端通过`/monitor/logininfor/list`接口发起分页请求，后端调用`startPage()`方法开启分页拦截，由MyBatis-Plus自动拼接`LIMIT`语句完成物理分页。

### 条件筛选SQL实现
MyBatis XML映射文件中定义了动态SQL查询逻辑，支持多条件组合筛选：

```xml
<select id="selectLogininforList" parameterType="SysLogininfor" resultMap="SysLogininforResult">
    select info_id, user_name, ipaddr, login_location, browser, os, status, msg, login_time 
    from sys_logininfor
    <where>
        <if test="ipaddr != null and ipaddr != ''">
            AND ipaddr like concat('%', #{ipaddr}, '%')
        </if>
        <if test="status != null and status != ''">
            AND status = #{status}
        </if>
        <if test="userName != null and userName != ''">
            AND user_name like concat('%', #{userName}, '%')
        </if>
        <if test="params.beginTime != null and params.beginTime != ''">
            AND login_time >= #{params.beginTime}
        </if>
        <if test="params.endTime != null and params.endTime != ''">
            AND login_time <= #{params.endTime}
        </if>
    </where>
    order by info_id desc
</select>
```

#### 支持的筛选条件：
- **按用户名模糊查询**：`userName LIKE '%xxx%'`
- **按IP地址模糊匹配**：`ipaddr LIKE '%xxx%'`
- **按登录状态精确匹配**：`status = '0'`
- **按时间范围筛选**：`login_time BETWEEN beginTime AND endTime`

查询结果按`infoId`降序排列，确保最新日志优先展示。

## 登录日志数据生命周期管理

系统提供了完整的登录日志生命周期管理策略，涵盖数据清理与归档机制。

### 清空操作
通过`cleanLogininfor()`方法执行清空操作，底层SQL为：
```sql
truncate table sys_logininfor
```
此操作会删除表中所有数据并重置自增ID，适用于测试环境或合规性要求下的数据清除。

### 批量删除
支持根据`infoIds`批量删除指定日志记录：
```xml
<delete id="deleteLogininforByIds" parameterType="Long">
    delete from sys_logininfor where info_id in
    <foreach collection="array" item="infoId" open="(" separator="," close=")">
        #{infoId}
    </foreach> 
</delete>
```

### 数据归档建议
虽然当前系统未实现自动归档功能，但建议通过以下方式管理历史数据：
1. **定时任务归档**：每月初将上月数据迁移至`sys_logininfor_history`历史表
2. **分区表设计**：按`login_time`进行RANGE分区，提升查询效率
3. **TTL策略**：设置3个月或6个月的数据保留周期，过期数据自动归档或删除

## loginTime字段索引优化建议

为提升高并发场景下的查询性能，应对`loginTime`字段建立合适的数据库索引。

### 当前问题
现有查询常按时间范围筛选（如“最近7天登录记录”），若无索引将导致全表扫描，严重影响性能。

### 优化方案
建议创建复合索引以覆盖常见查询场景：
```sql
CREATE INDEX idx_logininfor_time_status ON sys_logininfor (login_time DESC, status);
```

#### 索引优势：
- 加速`login_time BETWEEN ? AND ?`类查询
- 支持`ORDER BY login_time DESC`的有序输出
- 覆盖`status`过滤条件，减少回表次数

### 其他可选索引
| 索引名称 | 字段组合 | 适用场景 |
|--------|----------|----------|
| idx_logininfor_ip | (ipaddr) | 按IP地址频繁查询 |
| idx_logininfor_user | (user_name) | 按用户名快速定位 |
| idx_logininfor_composite | (login_time, user_name, status) | 多条件组合查询 |

## 后端服务记录用户登录行为示例

系统通过异步工厂类`AsyncFactory`统一处理登录日志的记录逻辑。

### 实现流程
1. 用户尝试登录（成功/失败）
2. 安全框架触发日志记录事件
3. `AsyncFactory.recordLogin`方法被调用
4. 构造`SysLogininfor`对象并插入数据库

### 核心代码逻辑
```java
public static TimerTask recordLogin(final String username, final String ip, final String address, 
                                   final String browser, final String os, final String msg, final String status) {
    return new TimerTask() {
        @Override
        public void run() {
            SysLogininfor logininfor = new SysLogininfor();
            logininfor.setUserName(username);
            logininfor.setIpaddr(ip);
            logininfor.setLoginLocation(address);
            logininfor.setBrowser(browser);
            logininfor.setOs(os);
            logininfor.setMsg(msg);
            // 状态转换：LOGIN_SUCCESS → 0, LOGIN_FAIL → 1
            if (StringUtils.equalsAny(status, Constants.LOGIN_SUCCESS, Constants.LOGOUT, Constants.REGISTER)) {
                logininfor.setStatus(Constants.SUCCESS);
            } else if (Constants.LOGIN_FAIL.equals(status)) {
                logininfor.setStatus(Constants.FAIL);
            }
            SpringUtils.getBean(ISysLogininforService.class).insertLogininfor(logininfor);
        }
    };
}
```

### 调用链路
```
LoginController → Security Framework → AsyncFactory.recordLogin() → SysLogininforService → SysLogininforMapper → DB
```

日志记录采用异步方式执行，避免阻塞主业务流程，保障登录响应速度。
